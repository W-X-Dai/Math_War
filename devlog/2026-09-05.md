# 2026-09-05 — 「微分防線」初版

## 摘要

建立可在 PC 瀏覽器遊玩的數學塔防遊戲「微分防線」。核心目標是讓入侵函數經過真實的代數與微積分轉換後化為 `0`，並以係數變化直接驅動敵人傷害。初版包含完整五波流程、公式工坊、八種算子、勝敗狀態、測試與正式版建置設定。

## 完成功能

- 建立 Vite 6.4.3、原生 ES modules 的單頁網頁遊戲，build target 為 ES2020，開發與預覽伺服器預設只綁定 `127.0.0.1`。
- 建立五路、八欄戰場；左側五欄可部署砲台，敵人依波次與路線由右向左推進。
- 實作算力資源、砲台費用與耐久、攻擊冷卻、敵人攔阻、基地傷害、消去獎勵、連鎖統計、暫停、雙倍速度、重新開始與勝敗流程。
- 實作五波內容及多項式、含常數項、雙變數、階乘係數風險與指數函數等敵人。
- 建立獨立數學領域模型，支援式子正規化、同類項合併、`x`／`y` 微分、多次微分、不定積分、定積分、常數平移、輸入反射、無窮極限、數值求值與格式化。
- 依「係數即傷害」延伸為所有項係數絕對值的總和；`x⁵` 的六次微分鏈會依序出現 `1、5、20、60、120、120` 傷害，常數再微分一次才歸零。
- 實作八種玩家算子：微分砲、參數平移砲、高階微分砲、定積分塔、不定積分、輸入反射、無窮極限及每波一次的全場偏微分。
- 建立公式與 `k` 雙佇列工坊。玩家能任意選取佇列中的公式與任意 `k`，預覽結果、消耗指定配對並組裝常數，而非被限制只能使用隊首。
- 組裝結果可安裝到 `P(x)−k` 的單一空槽，或依序安裝為定積分塔的下界與上界。
- 支援將任意公式卡、`k` 卡或已部署砲台拖入垃圾桶丟棄；聚焦項目後按 `Delete` 亦可完成相同操作。
- 支援 `1`～`8` 選擇算子、`Esc` 取消、`Space` 暫停，以及原生 Tab 焦點與 Enter 啟用操作。
- 加入公式追蹤、下一次微分預覽、係數傷害、距離、推導紀錄、波次提示、全場偏微分結果預覽、提示訊息及新手教學。
- 加入可選 Web Audio 回饋、分頁隱藏時自動暫停、ARIA 標籤、live region、鍵盤捷徑標示與 reduced-motion 樣式。
- 整合戰場、砲台、敵人與算子圖像資產，並保留採用的 PC 桌面視覺概念稿；目前沒有另外設計手機介面。
- 建立數學領域與遊戲引擎的 Node 測試，涵蓋六次微分、係數傷害、積分、極限、偏微分、定積分、任意佇列選取與丟棄、參數安裝、補牌上限及指數函數連鎖。
- 新增繁體中文 README，記錄安裝、開發、測試、建置、玩法、工坊、丟棄、鍵盤操作與專案架構。

## 重要設計決策

- 採用原生 JavaScript 與 DOM，而非加入 UI framework；除了 Vite 開發依賴外沒有產品執行期依賴，讓遊戲可維持小而直接的部署模型。
- 將 `domain/expression.js`、`game/engine.js`、`game/content.js` 與 `ui/` 分離。數學規則不依賴瀏覽器，遊戲狀態可用固定 seed 重現，畫面則只負責事件轉接與渲染。
- 以正規化後各項係數的 L1 總和計算傷害，讓常數項、負係數、雙變數項與指數項共用一致規則，也保留「操作錯誤會讓敵人變強」的風險。
- 敵人只在整個式子化為 `0` 時消滅；常數不是生命值，因此 `120` 必須再接受一次微分。這是 `x⁵` 需要六發而非五發的核心規則。
- 將持續型算子做成同路砲台，將反射、極限與不定積分做成單體即時操作，全場偏微分則需要確認預覽，避免三種互動語意混在一起。
- 工坊採「任選公式 × 任選 k」而非 queue top-only。佇列仍透過容量與補充冷卻形成壓力，但玩家可主動規劃參數，不會因排序被迫浪費關鍵組合。
- 將定積分界與平移參數都抽象成可組裝常數，使公式工坊同時服務多種砲台，而不增加另一套資源介面。
- 以受版本控制的圖像 atlas 呈現戰場與角色，CSS 負責配置、狀態與動效；視覺概念稿保留在 `docs/design/` 作為後續調整依據。

## 程序化章節與無限關卡（0.3.0）

### 摘要

將固定五波流程改為六個 seeded 主題章節與持續成長的無限章，並把固定算子列改成會補牌、消耗與任意整理的軍械 queue。這次也擴充數學基底、新增三座參數塔與三種敵人變異，讓每個 seed 能形成可重玩的解題路線。

### 完成功能

- 新增純函式 `generateFiniteWave(seed, chapterIndex)`、`generateEndlessWave(seed, round)` 及敵情摘要；關卡 RNG 與工坊／積分 RNG 分流。
- 建立多項式、常數、多項高階、多變數、對數分式及三角指數六章，地圖依序為 `4×7`、`4×8`、`5×9`、`5×10`、`6×11`、`6×12`，無限章固定為 `7×12`。
- 有限章固定 30 秒整備；無限整備按 `max(10, 32−2r)` 縮短。提早開始會依剩餘整秒發放每秒 `Σ5`、最多 `Σ150`。
- 章節開始會重設對應算力、砲台與三條 queues；有限章結束修復 `100 HP`。無限章首次重設，之後資源、軍械、工坊材料與砲台跨輪保留。
- 以容量八張、八秒補充的軍械 queue 取代固定算子列；成功使用才扣牌與算力，無效目標、取消或算力不足均不扣除。同一張新補軍械最多出現三張，並依下一輪需求加權。
- 軍械、公式、`k` 與砲台都能拖入垃圾桶任意丟棄，不限制 queue 位置；沒有另外加入丟棄按鈕。
- 表達式模型支援負整數次方、`aeᵇˣ`、三角式及 `axᵖln|x|`，涵蓋正規化、微積分、反射、極限、定積分、代入、傷害與格式化。奇點與超出有限基底的運算會明確拒絕。
- 新增 `f([ ])` 代入塔、`xD＋[ ]I` Euler 塔及 `D²＋[ ]I` 共振塔；公式工坊加入 `k`、`−k²`，上帝常數加入 `π` 與 `−π`。
- 新增快進、等式護盾與分裂變異。護盾會消耗攻擊但抵銷第一次公式轉換；分裂後的單項子敵人不會再次分裂。
- Vue 介面新增章節／無限輪與 seed HUD、整備倒數、提早獎勵、保密敵情摘要、函數族與變異徽章、動態 CSS 棋盤及同 seed／新 seed 結算操作。
- 版本由 `0.2.0` 提升至 `0.3.0`；沒有存檔格式或後端資料遷移。

### 重要設計決策

- 同一 seed 完整決定關卡與補給，但玩家的工坊及積分抽取保留在獨立 RNG stream，避免操作順序改寫之後章節的敵人安排。
- 生成器限制有限章最多四個可見基底、最高次方 6、最低次方 −4、頻率 2；無限章最多五項、最高次方 8、頻率 3。敵人數到 36 後改由速度、公式威脅及雙變異機率繼續成長。
- 整備與戰鬥都補三種 queue；queue 滿時保留當前倒數，不會在丟牌後瞬間補牌。算力自然補充只在戰鬥期間運作。
- 不定積分若會產生目前基底無法表示的 `(ln|x|)²`，會保留軍械、算力與 RNG 狀態並顯示原因，而不是產生錯誤式或吞掉資源。

### 驗證與限制

## GitHub Pages 子路徑部署修正

### 問題與修正

- 原先正式版使用 `/assets/...` 根路徑；固定成 `/Math_War/assets/...` 後雖適合 GitHub Pages，從 workspace 根目錄以 Live Server 開啟 `dist/index.html` 時仍會在錯誤層級尋找資源。CSS 的 404 回應被瀏覽器當成 `text/html`，因此觸發 MIME type 錯誤。
- 將 Vite `base` 改成相對路徑，讓入口、樣式與四張 atlas／背景圖都相對於 `dist/` 解析；同一份建置可部署在 GitHub Pages `/Math_War/`，也可放在任意本機子目錄。
- 新增 GitHub Pages Actions workflow，以 Node 18 執行乾淨安裝與正式建置，直接上傳 `dist/` artifact；Pages 不再依賴 branch 模式只支援 `/(root)` 或 `/docs` 的資料夾選單。
- README 補充正確的開發、正式預覽 URL、可攜式 Live Server 預覽與首次啟用 GitHub Actions 的設定步驟。

### 驗證與限制

- `npm test`：3 個測試檔全部通過。
- `npm run build`：Vite 成功產生 `./assets/...` 相對資源路徑。
- `npm run preview` 與 HTTP 檢查：HTML、CSS、JavaScript、戰場圖片皆回傳 `200`，內容型別分別正確為 `text/html`、`text/css`、`text/javascript` 與 `image/png`。
- Headless Chrome/CDP（1586 × 992）：頁面標題與遊戲內容正常，沒有 framework overlay、console error 或資源失敗；點擊「開始演算」後成功進入整備階段並顯示「提早開始」。Browser 外掛與 Playwright 仍不在環境中，因此沿用本機 Chrome 除錯協定驗證。
- GitHub repository 的 Pages Source 仍需由管理者在 Settings 中手動改選 GitHub Actions；本次只建立本機 workflow，沒有推送或部署。

## 公式彈頭命中結算

- 十一種軍械共用同一套飛行中投射物狀態；發射只建立彈頭及消耗該次資源，敵式、護盾、發散、消去獎勵與分裂全部延後到實際命中才結算。
- 命中時重新讀取敵人當下最外層的式子，讓同時抵達的多發攻擊依序作用，避免較晚命中的彈頭用發射時的舊式子覆蓋前一發結果。
- 全場偏微分仍對每個存活敵人分別降下一枚 `∂/∂x`，各目標依自己的彈頭抵達時間獨立結算；目標提前消失時該彈落空，不會轉向或重複提供獎勵。
- 戰場移除所有彈頭連接射線，只保留會跟隨模擬時鐘移動的公式彈頭與接觸瞬間的命中脈衝；暫停會同時凍結彈頭位置、命中倒數與效果壽命。
- `npm test`、正式版建置與 diff 檢查通過；引擎回歸涵蓋精確命中門檻、暫停、並發重算、落空、基地漏怪、全場錯峰、空場不消耗，以及最後命中脈衝期間不推進資源或 RNG。

## 戰術章節、保障補給與砲塔回收（0.7.0）

### 摘要

把六章從單次隨機正式波重整成「辨識、壓力、混合」三段節奏，並將必要反制從抽牌機率移到每段明確保障。正式防線與資源改為跨章延續；玩家若要調整舊塔，必須主動把回收鏟拖到砲台，並取得原價一半算力。

### 完成功能與設計決策

- 六章依序改為基礎防線、階乘危機、漸近突破、組合推導、週期防線及指數交鋒；每章保留獨立教學沙盒作辨識段，再生成壓力段與混合段。
- 新增 `generateFiniteSegment(seed, chapterIndex, segmentIndex)`，保留 `generateFiniteWave` 相容入口。正式段以兩至三隻同路小隊出場；混合段可同時施壓兩路，但每一路在該段維持固定函數族與反制參數。
- 限制普通分式、三角、指數與多變數公式的難度維度；有限敵人最多一種變異，護盾不再同時快進，分裂子怪仍能由原路防線處理。無限模式改為逐輪單軸增加敵數、同步路數、變異、速度或公式複雜度。
- 每個正式段產生 `counterRequirements`、精確 `guaranteedSupply` 與 `summary.lanes`。保障牌直接加入且可暫時超過容量，隨機補牌等 queue 降回容量以下才繼續；例如參數 `−4` 會直接給 `−k²` 與 `k=2`。
- 正式砲台、算力、三條 queues 及常數庫會跨段、跨章並延續到無限模式；章節教學只暫時換成固定教具，結束後完整還原。每章不另發算力，提早開始獎勵只在壓力段發一次。
- D² 調為 `Σ150／2.2 秒`，代入塔調為 `Σ130／6 秒`；Euler 與極限提前至第三章，共振塔移至第五章。代入 `f(k)` 現在只替換 `x`，不會偷偷把自由變數 `y` 設為零。
- 移除砲台拖入垃圾桶及點擊切換休眠。新增可拖曳的回收鏟、點按武裝與鍵盤 `Delete` 等價操作；玩家塔回收返還原價 `50%`，教學預置塔仍不可回收。參數塔只會因實際運算錯誤自動停火，重新裝填後恢復。
- 版本由 `0.6.0` 提升為 `0.7.0`。沒有存檔或後端資料遷移；有限關卡的 seeded 內容刻意改變，舊 `generateFiniteWave(seed, chapterIndex)` 呼叫仍會取得該章壓力段。

### 驗證與限制

- `npm test`：8 個測試檔通過；其中生成器以 500 個 seeds 驗證逐路穩定、正確數學、第三章起純 D 不足、精確保障材料、公式複雜度與變異限制。

## 解鎖式獨立關卡（0.8.0）

### 摘要

將原本會自動跨章延續資源的線性戰役改為六個可重玩的獨立關卡。玩家從關卡地圖逐關解鎖；第六關完成後開放使用固定完整配置開始的無限證明。

### 完成功能與設計決策

- 新增版本化本機進度 `{ version: 1, completedLevelIds }`，只保存連續的已通關關卡 ID；無效、損壞或無法存取的資料會安全回到只開放第一關。
- `createGame(seed, options)` 支援指定有限關、略過教學及獨立無限模式。有限關會重置基地、資源、砲台與統計，只在壓力／混合段之間延續；同 seed 的程序敵情維持不變。
- 有限關混合段完成後停在 `won` 結算，不再自動換章或修復基地。教學仍是以該關正式起始配置為快照的沙盒，也可在選關詳情中只對本次略過。
- 新增獨立選關畫面、通關／失敗結算及離關／清除進度確認。鎖定卡保留關名與主題，已解鎖卡顯示棋盤、流程、新敵人與新軍械。
- 版本由 `0.7.0` 提升至 `0.8.0`。沒有後端或帳號資料遷移；既有版本沒有關卡存檔，因此新的 localStorage schema 從空進度開始。

### 驗證與限制

- 自動化測試新增六關直接開局、獨立起始資源、教學略過／還原、有限關勝利終點、無限起始牌組，以及進度正規化、解鎖、冪等完成與 storage 失敗處理。
- `npm test`：9 個測試檔全部通過；輸出至 `/tmp` 的 Vite 正式建置也成功完成，沒有改寫既有 `dist/`。
